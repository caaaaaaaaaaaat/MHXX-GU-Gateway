# V338 · 队列背压不再踢人

V337 之后继续排查剩下的掉线路径，本轮找到并修掉了三处「玩家自身没有故障，却被网关主动断开」的情形。V337 修的是房间链路超时，本版修的是队列与 ENet 缓冲。

- **队列满不再断开玩家（主要改动）。** 此前每客户端的收/发队列一旦写满，网关就直接关掉这个 Citra 会话，日志里是「outbound queue limit」/「inbound queue limit」。三人、四人局里房间广播量随人数上升，一次瞬时突发就可能把某个玩家挤掉——而这与玩家自己网络好坏无关。现在默认改为**丢弃超出的那一帧、保留会话**，并新增 `outbox_dropped`/`inbox_dropped` 计数区分「丢帧」与「断线」。需要旧行为时可用 `--queue-policy close` 切回。
- **Citra 侧 ENet 缓冲容量修正。** 网关原先把自己 256 KiB 的应用层收包上限直接当成 ENet 每对端的重组预算，而 ENet 厂商默认是 32 MiB（相差 128 倍）。超过该预算时 ENet 会直接重置该 peer，等于由库层面强制掉线。现在独立为 4 MiB 的专用上限，应用层队列仍由上面的丢帧策略守护。
- **房间链路超时档案可配置。** V337 的 5000/30000 ms 已可在命令行/设置里调整（`--joined-timeout-min` / `--joined-timeout-max`，1..60000 ms），现场遇到弱网可以加宽重传窗口而不必改代码；连接建立阶段仍保留快速失败。

另有两个 DSH 侧的可观测性收益：`counters.json` 现在能直接看出「丢帧」而不是「断线」，排查现场掉线时不必再靠推断。

GUI 版本号升为 V338，行为默认值即上述新策略，界面无新增操作项。

本版通过 1873 项核心回归（48 组，含新增 B338 稳定组）、155 项 PowerShell 证据断言、传输回环、以及设置/后端/隐藏窗口检查。掉线是否彻底收敛仍需真实公网多人环境验证；自动测试不等同于现场验收。
