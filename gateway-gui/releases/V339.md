# V339 · 房间容量交给房间自己说

V338 之后把网关核心同步到了服务端那一版。本版对桌面版唯一的行为变化在「房间满」这一判断上。

- **房间容量改为连上房间后自动检测。** 桌面版从不设置 `room_capacity`，核心默认值是 0（未知）。在此之前，容量未知意味着网关本地不做任何「房间满」判断，全部交给远端房间服务器回答。现在网关收到房间的 `RoomInformation` 后记下它报告的 `member_slots`，用这个真实值做本地满员判断；答复 Citra 的 `0c`（房间满）时用的是房间自己声明的容量，而不是任何猜测或固定值。多故障同时存在时的答复顺序（满 → 密码 → 昵称 → MAC → 主机 ID → 版本）与真实 Citra 服务器保持一致。房间始终是容量的唯一权威：房间若从不报告，检查保持禁用，行为与旧版相同。
- **同批同步的其它核心改动对桌面版没有可观测影响。** 监听地址与远端房间地址的非回环限制被移除、`--room` 支持域名并由 ENet 在连接时解析、`--seconds 0` 改为常驻、以及为 Linux 构建做的条件编译——这些分别面向命令行版和容器部署。桌面版本来就传已解析的 IPv4，且不经过这些参数路径，因此 Windows 构建行为与 V338 等价。

GUI 版本号升为 V339，界面无新增操作项，设置文件与既有格式一致，升级后原有设置继续生效。

本版通过 1882 项核心回归（48 组，含新增的 B339 容量组）、33 项后端检查、设置读写与 CLI 参数检查，以及隐藏窗口冒烟（创建、定时器、优雅关闭，未启动网络）。房间容量自动检测的现场意义（玩家不再被误判的「房间已满」拦下）仍需真实多人房间验证；自动测试不等同于现场验收。

下载 `XXGU-Gateway-V339-release-win64.zip`，解压后双击 `XXGU-Gateway.exe`，按照 `使用说明.md` 连接。

对应源码与构建脚本另见 `XXGU-Gateway-V339-source.zip`。用户包仅含程序和使用说明，开源许可合并在使用说明末尾。
